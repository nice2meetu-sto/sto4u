# 서울관광재단 인력현황 관리 시스템

2023.12.30 기준 재직자 명부(스냅샷)에 그 이후의 **인사발령 로그**를 *조회 기준일까지* 순서대로 적용(리플레이)하여,
임의 날짜의 **현원표(일일·직급별)** 와 **전체 재직자 명단**을 재구성해 보여주는 단일 페이지 웹앱입니다.

- **단일 HTML + 순수 JavaScript** (빌드 스텝·번들러·프레임워크 없음) — GitHub Pages에 그대로 호스팅
- 데이터는 **Google Apps Script GET JSON API** 를 `fetch` 로 읽음 (POST·`google.script.run` 미사용)
- 브라우저 스토리지 미사용 — 상태는 메모리(JS 변수)로만 관리
- 모든 날짜는 **KST 기준**

---

## 파일 구조

```
/index.html   # 단일 페이지 웹앱 (HTML + CSS + JS 한 파일)
/Code.gs      # Google Apps Script (스프레드시트에 붙여넣어 배포)

```

## 1. 구글 시트 준비

하나의 스프레드시트에 아래 탭을 만듭니다. (1행 = 가로 헤더, 2행부터 데이터)

### 탭 `부서마스터` (부서의 시점별 속성 — 조직개편/표시순서의 단일 출처)
**부서코드별로** 부서명·본부·표시순서를 관리합니다. 팀명 변경·본부 이동·표시순서 변경은 **이 탭에 1줄만** 추가하면 조회일 기준으로 정확히 반영됩니다(인사발령 불필요).

| 부서코드 | 부서명 | 본부 | 표시순서 | 적용일 | 비고 |
|---|---|---|---|---|---|
| D101 | 기획조정팀 | 기획경영본부 | 1 | 2023-12-30 | 최초 |
| D101 | **기획전략팀** | 기획경영본부 | 1 | 2024-07-01 | 팀명변경 |
| D205 | 마케팅팀 | 관광산업본부 | 5 | 2023-12-30 | |
| D205 | 마케팅팀 | **국제관광MICE본부** | 3 | 2025-01-01 | 본부이동 |

- **`부서코드`** = 절대 바뀌지 않는 키. 같은 코드에 `적용일` 별로 여러 줄을 쌓습니다.
- 조회일 기준 **`적용일 ≤ 조회일` 중 가장 최근 줄**이 그 시점의 부서명/본부/표시순서가 됩니다.
- **`표시순서`** = 본부 안에서 부서가 나열되는 순서(작은 값이 먼저). 본부 자체의 순서는 `index.html` 의 `BONBU_ORDER`.

### 탭 `기초명부` (2023.12.30 기준 · 1행 1명)
| 사원코드 | 사원명 | 부서코드 | 직급 | 고용형태 | 성별 | 근무지 | 입사일 | 상태 |
|---|---|---|---|---|---|---|---|---|
| 고유키 | | **부서마스터의 코드** | `임원`/`1급`~`6급`/`전문직 가·나·다·라` | `일반직`/`전문직`/`기간제`/`파견` | `남`/`여` | 센터·사업장명 | 날짜 | `재직`/`휴직`/`휴가`/`파견`/`기타` |

> 사람은 **부서코드로만** 소속을 가집니다. 부서명/본부/표시순서는 부서마스터에서 조회일 기준으로 자동 결정됩니다.
> 퇴사일 컬럼은 두지 않습니다. 퇴사는 인사발령 로그의 사건으로만 기록합니다.
> (선택) `부서` 컬럼을 같이 둘 수 있으나, **부서코드가 있으면 마스터값이 우선**합니다. 부서코드가 빈 인원만 `부서` 값으로 폴백 표시됩니다.

### 탭 `인사발령` (2023.12.31 이후 · 1행 1건)
| 발령일 | 사원코드 | 사원명 | 변동구분 | 변경부서코드 | 변경직급 | 변경근무지 | 변경고용형태 | 성별 | 비고 |
|---|---|---|---|---|---|---|---|---|---|
| 효력일(=반영일) | 매칭키(신규입사는 새 코드) | | 아래 표 참조 | 부서/본부 이동 시 | 승급 시 | 근무지이동 시 | 변경 시 | 입사 시 신규값 | 자유기재 |

**변동구분 의미**

| 변동구분 | 동작 |
|---|---|
| `입사` | 행 추가 (변경부서코드/직급/근무지/고용형태/성별 신규값 사용) |
| `퇴사` | 발령일 이후 집계 제외 (발령일 = 실제 퇴직일) |
| `부서이동` | **개인**이 다른 부서로 이동 → `변경부서코드` 로 갱신. (그 사람의 본부도 마스터에서 자동으로 따라옴) |
| `근무지이동` | `변경근무지` 로 갱신 |
| `승급` | `변경직급` 으로 갱신 |
| `휴직` / `파견` | 상태 → `휴직` / `파견` (사고내역) |
| `복직` | 상태 → `재직` (휴직·파견 복귀 모두 포함) |

> **복합 발령 지원**: 한 발령 행에 여러 `변경*` 값을 같이 넣으면 **변동구분과 무관하게 모두 반영**됩니다. 예) `복직`하면서 부서·근무지·직급이 같이 바뀌면 `변동구분=복직` 행에 `변경부서코드`·`변경근무지`·`변경직급`을 함께 적으면 한 번에 처리됩니다. (입사/퇴사 제외)
> **역할 분담**: *부서 자체의 변화(팀명·본부·순서)* 는 **부서마스터**, *사람의 이동* 은 **인사발령(`변경부서코드`)**.
> 표기 흔들림은 동의어로 자동 흡수됩니다. 예) `퇴직`→`퇴사`, `전보`→`부서이동`, `승격`→`승급`, `복귀`/`파견복귀`→`복직`, `계약직`→`기간제`. 매핑은 `index.html` 상단 `ORDER_TYPE_SYNONYMS` / `EMP_SYNONYMS` / `STATUS_SYNONYMS` 에서 조정합니다.

### 처음 세팅 / 마이그레이션 순서
1. **부서마스터 탭 생성** → 현재 존재하는(또는 과거에 존재했던) 모든 부서에 **부서코드**를 하나씩 부여하고, 부서명·본부·표시순서·적용일(`2023-12-30`)로 한 줄씩 입력.
   - 과거에 팀명/본부가 바뀐 이력이 있으면, 같은 부서코드로 **적용일별 줄을 추가**해 역사까지 채워두면 됩니다.
2. **기초명부**에 `부서코드` 컬럼 추가 → 각 인원에 해당 부서코드 입력. (부서명 컬럼은 지워도 되고, 폴백용으로 남겨둬도 됨)
3. **인사발령**의 부서이동 관련 컬럼을 `변경부서코드`로 정리. (개인이 옮겨간 팀의 부서코드 입력)
4. 화면 새로고침 → 상단 경고 배너가 없으면 코드 연결 정상. 2023-12-30 조회로 검수표(7번)와 대조.

## 2. Apps Script 배포 (GET JSON API)

1. 스프레드시트에서 **확장 프로그램 → Apps Script** 열기
2. 기본 `Code.gs` 내용을 본 저장소의 [`Code.gs`](./Code.gs) 로 교체
3. 탭 이름이 다르면 상단 `SHEET_BASE` / `SHEET_ORDERS` / `SHEET_QUOTA` / `SHEET_DEPT` / `SHEET_EMAP` 수정
4. **배포 → 새 배포 → 유형: 웹 앱**
   - **실행 계정: 나(본인)**
   - **액세스 권한: 모든 사용자(Anyone)** ← CORS·인증 없이 GET 호출되도록 필수
5. 발급된 **웹 앱 URL** 복사 (`https://script.google.com/macros/s/.../exec`)
6. 브라우저에서 `웹앱URL?action=data` 직접 열어 JSON(`{ "base":[...], "orders":[...], "quota":[...], "dept":[...], "emap":[...] }`)이 나오는지 확인

> 시트 데이터를 바꾼 뒤에는 재배포가 필요 없습니다(같은 배포가 항상 최신 시트를 읽음). 단, **Code.gs 코드를 수정**하면 같은 배포에 대해 **새 버전으로 재배포**해야 반영됩니다.

## 5. 화면 사용법

- **상단 컨트롤**: 조회 기준일 날짜 피커 + 타임라인 슬라이더(발령일 분포 따라 이동) + `◀발령 / 발령▶`(발령일 단위 이동). 기준일을 바꾸면 모든 탭이 즉시 재계산됩니다. `↻ 새로고침` 으로 시트를 재요청하고, 헤더에 마지막 동기화 시각이 표시됩니다.
- **① 일일**: 부서 × 고용형태(일반직/전문직/기간제/파견, 각 남/여/소계) + 합계 + 사고내역(휴직/휴가/파견/기타/계) + 현재인원.
  `현재인원 = 합계 소계 − 사고내역 계`. **부서명 클릭 → 구성원 명단 모달.**
- **② 직급별**: 부서 × 직급(임원/1급~6급/전문직, 각 남/여/계) → 소계 → 기간제 → 총계.
  `소계 = 임원 + 1급~6급 + 전문직`(정원 내), `총계 = 소계 + 기간제`(정원 외).
- **③ 전체 재직자**: 기준일 전체 명부(사원코드·사원명·부서코드·부서·직급·고용형태·근무지·입사일·상태). 검색(이름/부서/직급/코드)·필터·정렬, **엑셀(CSV) 다운로드**(UTF-8 BOM, Excel 한글 호환).
- **④ 인사발령 등록**: 공통 항목 + 대상자 표로 여러 명 동시 발령 입력 → 사원코드·부서코드 자동 변환 후 시트에 저장. (자세히는 8번)

### 부서 표시 순서 (본부순 → 표시순서)
부서 행은 **본부순으로 묶인 뒤, 본부 안에서 `표시순서` 번호대로** 나열됩니다.
1. **본부 순서**: `index.html` 의 `BONBU_ORDER` 에 나열한 순서(대표이사실→직속부서→기획경영본부→국제관광MICE본부→관광산업본부). 본부명은 대소문자·공백 무시로 매칭됩니다.
2. **본부 안 부서 순서**: `부서마스터`의 `표시순서`(작은 값 먼저). 순서를 바꾸려면 마스터의 표시순서만 고치면 됩니다(발령 불필요).
3. (특수) 부서 순서를 코드에서 완전 수동 지정하려면 `index.html` 의 `DEPT_ORDER` 사용.

### 조직개편 입력 치트시트
| 상황 | 어디에 입력 | 줄 수 |
|---|---|---|
| 팀 이름만 변경 | **부서마스터**에 같은 부서코드 + 새 부서명 + 적용일 | 1줄 |
| 팀이 다른 본부로 이동 | **부서마스터**에 같은 부서코드 + 새 본부 + 적용일 | 1줄 |
| 표시순서 변경 | **부서마스터**에 같은 부서코드 + 새 표시순서 + 적용일 | 1줄 |
| 신설팀 생성 | **부서마스터**에 새 부서코드 1줄 + 그 팀으로 가는 사람마다 `변경부서코드` 발령 | 1 + N |
| 개인이 다른 팀으로 이동 | **인사발령** `부서이동` + `변경부서코드` | 1명당 1줄 |
| 팀 통째 이동(인원 그대로, 코드 유지) | 부서마스터 1줄(본부 변경)로 충분 | 1줄 |

> 핵심: 같은 부서코드를 유지하면 **사람을 건드리지 않고** 마스터 1줄로 끝납니다. 조회일 기준 옛/새 이름·본부가 역사적으로 정확히 표시됩니다.

### 사고내역 인원 위치 — 모드 A (확정)
상태가 `재직` 이 아닌 인원(휴직/휴가/파견/기타)은 집계상 정원외 버킷 부서 **`인재경영팀(임)`** 으로 이동시켜 표시합니다(직급은 유지). 첨부 엑셀 숫자와 일치하는 기준입니다. `index.html` 의 `HOLD_BUCKET_MODE` / `HOLD_BUCKET_DEPT` 로 제어합니다.

## 6. 핵심 알고리즘 (발령 리플레이)

```
rosterAsOf(기준일):
  roster = deepcopy(기초명부)              # 각 인원: 부서코드 보유
  orders = 인사발령.filter(발령일 <= 기준일).sort(발령일 asc, 그다음 입력순)
  for o in orders:
    입사 → 추가 / 퇴사 → 제거 / 부서이동 → 변경부서코드 / 근무지이동·승급 → 해당 필드
    휴직·파견 → 상태 변경 / 복직 → 재직 / (변경고용형태 있으면 함께 갱신)
  for p in roster:                         # 부서 속성 확정
    p.부서/본부/표시순서 = 부서마스터.resolve(p.부서코드, 기준일)   # 적용일 ≤ 기준일 중 최신
  return roster
```
이 단일 `roster` 를 피벗하여 일일표·직급별표·전체명단 세 화면을 그립니다. 날짜는 `yyyy-MM-dd` 문자열로 비교하므로 타임존 오프셋 문제가 없습니다. 부서명/본부/표시순서는 **저장하지 않고 조회일마다 마스터에서 계산**하므로, 마스터 1줄 수정이 모든 과거·현재 화면에 일관되게 반영됩니다.

## 8. 인사발령 등록 탭 (④)

웹앱 안에서 바로 인사발령을 입력해 시트에 저장하는 탭입니다.

- **공통 항목**(발령일·변동구분·변경직급·변경근무지·변경고용형태·비고)은 한 번만 입력 → 대상자 전원에게 동일 적용.
- **대상자 표**에서 `＋ 인원 추가` 로 행을 늘려 **사원명·변경부서(부서명)** 만 개별 입력. (같은 발령을 여러 명에게 동시에)
- 입력하는 즉시:
  - **사원코드** = `기타_사원코드` 에서 사원명으로 자동 변환(미리보기).
  - **변경부서코드** = 입력한 부서명을 **발령일 기준**으로 부서마스터에서 변환(예: `경영지원팀`+`2024-01-03` → `D214`). 부서명/공백 차이는 무시.
- `시트에 저장` → 대상자 한 명당 `?action=addOrder` GET 으로 **인사발령 탭에 1행씩** append. 행별 성공/실패가 표시되고, 저장 후 자동 재동기화됩니다.

> **부서 변경은 코드로 저장됩니다.** 등록 탭은 입력한 부서명을 발령일 기준 코드로 변환해 **`변경부서` 열에 코드(예: D214)** 를 기록합니다(`변경부서코드` 열이 따로 있으면 거기에도 동일 코드 기록). 재구성 로직은 `변경부서`/`변경부서코드` 어느 쪽 값이든 **부서마스터의 코드면 코드로, 부서명이면 발령일 기준으로 코드로 변환**해 인식합니다.
> 저장은 쓰기 동작이므로 Apps Script 배포의 **액세스=모든 사용자**, **실행=본인**이어야 합니다(소유자 권한으로 append).
> `SCRIPT_URL` 이 비어 있는 데모 모드에서는 미리보기만 되고 저장은 비활성화됩니다.
