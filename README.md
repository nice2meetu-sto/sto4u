# 서울관광재단 인력현황 관리 시스템

2023.12.30 기준 재직자 명부(스냅샷)에 그 이후의 **인사발령 로그**를 *조회 기준일까지* 순서대로 적용(리플레이)하여,
임의 날짜의 **현원표(일일·직급별)** 와 **전체 재직자 명단**을 재구성해 보여주는 단일 페이지 웹앱입니다.

- **단일 HTML + 순수 JavaScript** (빌드 스텝·번들러·프레임워크 없음) — GitHub Pages에 그대로 호스팅
- 데이터는 **Google Apps Script GET JSON API** 를 `fetch` 로 읽음 (POST·`google.script.run` 미사용)
- 브라우저 스토리지 미사용 — 상태는 메모리(JS 변수)로만 관리
- 모든 날짜는 **KST 기준**

---

## 파일 구조

```
/index.html   # 단일 페이지 웹앱 (HTML + CSS + JS 한 파일)
/Code.gs      # Google Apps Script (스프레드시트에 붙여넣어 배포)
/README.md    # 본 문서
```

## 1. 구글 시트 준비

하나의 스프레드시트에 아래 **3개 탭**을 만듭니다. (1행 = 가로 헤더, 2행부터 데이터)

### 탭 `기초명부` (2023.12.30 기준 · 1행 1명)
| 사원코드 | 사원명 | 부서 | 직급 | 고용형태 | 성별 | 근무지 | 입사일 | 상태 |
|---|---|---|---|---|---|---|---|---|
| 고유키 | | | `임원`/`1급`~`6급`/`전문직 가·나·다·라` | `일반직`/`전문직`/`기간제`/`파견` | `남`/`여` | 센터·사업장명 | 날짜 | `재직`/`휴직`/`휴가`/`파견`/`기타` |

> 퇴사일 컬럼은 두지 않습니다. 퇴사는 인사발령 로그의 사건으로만 기록합니다.

### 탭 `인사발령` (2023.12.31 이후 · 1행 1건)
| 발령일 | 사원코드 | 사원명 | 변동구분 | 변경부서 | 변경직급 | 변경근무지 | 변경고용형태 | 성별 | 비고 |
|---|---|---|---|---|---|---|---|---|---|
| 효력일(=반영일) | 매칭키(신규입사는 새 코드) | | 아래 표 참조 | 부서이동 시 | 승급 시 | 근무지이동 시 | 변경 시 | 입사 시 신규값 | 자유기재 |

**변동구분 의미**

| 변동구분 | 동작 |
|---|---|
| `입사` | 행 추가 (변경부서/직급/근무지/고용형태/성별 신규값 사용) |
| `퇴사` | 발령일 이후 집계 제외 (발령일 = 실제 퇴직일) |
| `부서이동` | `변경부서` 로 갱신 — **조직 개편/팀명 변경도 구성원 전원에게 한 줄씩 부서이동 발령** |
| `근무지이동` | `변경근무지` 로 갱신 |
| `승급` | `변경직급` 으로 갱신 |
| `휴직` / `파견` | 상태 → `휴직` / `파견` (사고내역) |
| `복직` | 상태 → `재직` (휴직·파견 복귀 모두 포함) |

> 표기 흔들림은 동의어로 자동 흡수됩니다. 예) `퇴직`→`퇴사`, `전보`→`부서이동`, `승격`→`승급`, `복귀`/`파견복귀`→`복직`, `계약직`→`기간제`. 매핑은 `index.html` 상단 `ORDER_TYPE_SYNONYMS` / `EMP_SYNONYMS` / `STATUS_SYNONYMS` 에서 조정합니다.

### 탭 `정원` (선택)
직급별 정원 1행. 정현원 현황표를 1차 범위에서 제외하면 비워두어도 됩니다.

## 2. Apps Script 배포 (GET JSON API)

1. 스프레드시트에서 **확장 프로그램 → Apps Script** 열기
2. 기본 `Code.gs` 내용을 본 저장소의 [`Code.gs`](./Code.gs) 로 교체
3. 탭 이름이 다르면 상단 `SHEET_BASE` / `SHEET_ORDERS` / `SHEET_QUOTA` 수정
4. **배포 → 새 배포 → 유형: 웹 앱**
   - **실행 계정: 나(본인)**
   - **액세스 권한: 모든 사용자(Anyone)** ← CORS·인증 없이 GET 호출되도록 필수
5. 발급된 **웹 앱 URL** 복사 (`https://script.google.com/macros/s/.../exec`)
6. 브라우저에서 `웹앱URL?action=data` 직접 열어 JSON(`{ "base":[...], "orders":[...], "quota":[...] }`)이 나오는지 확인

> 시트 데이터를 바꾼 뒤에는 재배포가 필요 없습니다(같은 배포가 항상 최신 시트를 읽음). 단, **Code.gs 코드를 수정**하면 같은 배포에 대해 **새 버전으로 재배포**해야 반영됩니다.

## 3. SCRIPT_URL 입력

`index.html` 상단의 상수에 2단계에서 받은 URL을 붙여넣습니다.

```js
const SCRIPT_URL = "https://script.google.com/macros/s/AKfycb.../exec";
```

> 비워두면(`""`) 내장 **데모 데이터**로 동작합니다. 화면 동작 확인용입니다.

## 4. GitHub Pages 배포

1. 이 저장소를 GitHub에 푸시
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch**
3. 브랜치 선택(예: `main`) · 폴더 `/ (root)` → 저장
4. 잠시 후 `https://<사용자>.github.io/<저장소>/` 에서 `index.html` 접속

## 5. 화면 사용법

- **상단 컨트롤**: 조회 기준일 날짜 피커 + 타임라인 슬라이더(발령일 분포 따라 이동) + `◀발령 / 발령▶`(발령일 단위 이동). 기준일을 바꾸면 모든 탭이 즉시 재계산됩니다. `↻ 새로고침` 으로 시트를 재요청하고, 헤더에 마지막 동기화 시각이 표시됩니다.
- **① 일일**: 부서 × 고용형태(일반직/전문직/기간제/파견, 각 남/여/소계) + 합계 + 사고내역(휴직/휴가/파견/기타/계) + 현재인원.
  `현재인원 = 합계 소계 − 사고내역 계`. **부서명 클릭 → 구성원 명단 모달.**
- **② 직급별**: 부서 × 직급(임원/1급~6급/전문직, 각 남/여/계) → 소계 → 기간제 → 총계.
  `소계 = 임원 + 1급~6급 + 전문직`(정원 내), `총계 = 소계 + 기간제`(정원 외).
- **③ 전체 재직자**: 기준일 전체 명부. 검색(이름/부서/직급)·필터·정렬, **엑셀(CSV) 다운로드**(UTF-8 BOM, Excel 한글 호환).

### 사고내역 인원 위치 — 모드 A (확정)
상태가 `재직` 이 아닌 인원(휴직/휴가/파견/기타)은 집계상 정원외 버킷 부서 **`인재경영팀(임)`** 으로 이동시켜 표시합니다(직급은 유지). 첨부 엑셀 숫자와 일치하는 기준입니다. `index.html` 의 `HOLD_BUCKET_MODE` / `HOLD_BUCKET_DEPT` 로 제어합니다.

## 6. 핵심 알고리즘 (발령 리플레이)

```
rosterAsOf(기준일):
  roster = deepcopy(기초명부)
  orders = 인사발령.filter(발령일 <= 기준일).sort(발령일 asc, 그다음 입력순)
  for o in orders:
    입사 → 추가 / 퇴사 → 제거 / 부서이동·근무지이동·승급 → 해당 필드 갱신
    휴직·파견 → 상태 변경 / 복직 → 재직 / (변경고용형태 있으면 함께 갱신)
  return roster
```
이 단일 `roster` 를 피벗하여 일일표·직급별표·전체명단 세 화면을 그립니다. 날짜는 `yyyy-MM-dd` 문자열로 비교하므로 타임존 오프셋 문제가 없습니다.

## 8. (2차 범위) 인사발령 등록

`Code.gs` 에 `?action=addOrder` GET 핸들러가 포함되어 있습니다. 헤더 키와 동일한 쿼리 파라미터로 호출하면 인사발령 탭에 1행이 append 됩니다.

```
웹앱URL?action=addOrder&발령일=2024-08-01&사원코드=E010&사원명=홍길동&변동구분=입사&변경부서=관광사업팀&변경직급=6급&변경고용형태=일반직&성별=남&변경근무지=센터A
```
프런트 등록 폼은 향후 추가 예정입니다.
